## About this SDK

DreamApply publishes no OpenAPI description, so there was nothing to generate from
directly. Their own PHP SDK, [dream-group/dream-apply-sdk](https://github.com/dream-group/dream-apply-sdk),
turned out to be the better source: it is itself **@generated**, and its **gen/**
directory encodes field names, types, nullability, enum domains and URL structure.

The spec in [.sdk/def/](.sdk/def/) was derived from it **mechanically**, by the
script committed alongside it. Nothing was hand-written, and re-running the script
against a fresh checkout reproduces the spec byte for byte. See
[.sdk/def/README.md](.sdk/def/README.md) for the full mapping.

### What that means for accuracy

Being honest about where this is solid and where it is not:

- Field names, types, nullability and enum values come from the vendor's own
  generated code, so they are as good as their SDK.
- **HTTP verbs are inferred** from the SDK's base classes and traits, not declared.
- **PHP types carry no JSON formats**, so dates arrive as plain strings.
- **The SDK may lag the live API** — last upstream push 2025-12-18, tracking v8.
- **Nothing here has been run against a live instance.** DreamApply has no
  self-serve sandbox, so no request in this SDK has been executed against a real
  server. Treat it as a well-founded draft, not a tested client.

If any of that is wrong, the fix belongs in the derivation script, not in the
generated output.

## Entities, not endpoints

This SDK exposes the API as **14 semantic entities** that you
call directly, instead of assembling URL paths and query strings. See the [Entities](#entities) table below for the full list. Entities are
**Capitalised** to mark them as the primary surface, each with the operations they
support (`list`, `load`, `create`, `remove`):

```ts
const client = new DreamapplySDK()
const items = await client.AcademicTerm().list()
```

Thinking in entities keeps the mental model small — for people and AI agents alike —
rather than reasoning about raw HTTP routes and query parameters.

## Offline unit testing

Every SDK ships a built-in **test mode** that swaps the HTTP transport for
an in-memory mock, so your unit tests run fully offline — no server, no
network, and no credentials:

### TypeScript

```ts
const tableviews = await client.TableView().list()

```


## Quickstart in other languages

### Python

```python
import os

client = DreamapplySDK({
    "apikey": os.environ.get("DREAMAPPLY_APIKEY"),
})
```

## Direct and prepare

For endpoints the entity model doesn't cover, use the low-level methods:

- **`direct(fetchargs)`** — build and send an HTTP request in one step.
- **`prepare(fetchargs)`** — build the request without sending it.

Both accept a map with `path`, `method`, `params`, `query`,
`headers`, and `body`. See the [How-to guides](#how-to-guides) below.

## How-to guides

### Make a direct API call

When the entity interface does not cover an endpoint, use `direct`:

**TypeScript:**
```ts
const result = await client.direct({
  path: '/api/resource/{id}',
  method: 'GET',
  params: { id: 'example' },
})
if (result instanceof Error) {
  throw result
}
console.log(result.data)
```

**Python:**
```python
result = client.direct({
    "path": "/api/resource/{id}",
    "method": "GET",
    "params": {"id": "example"},
})
```

**Go:**
```go
result, err := client.Direct(map[string]any{

    "method": "GET",
    "params": map[string]any{"id": "example"},
})
if err != nil {
    panic(err)
}
fmt.Println(result)
```

## Advanced

> Everyday use only needs the sections above. This explains the internals
> behind every call — relevant when writing custom features.

Every SDK call runs the same five-stage pipeline:

1. **Point** — resolve the API endpoint from the operation definition.
2. **Spec** — build the HTTP specification (URL, method, headers, body).
3. **Request** — send the HTTP request.
4. **Response** — receive and parse the response.
5. **Result** — extract the result data for the caller.

A feature hook fires at each stage (e.g. `PrePoint`, `PreSpec`,
`PreRequest`), so features can inspect or modify the pipeline without
forking the SDK.
